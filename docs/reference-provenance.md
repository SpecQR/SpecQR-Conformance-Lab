# Fixed-segmentation reference evidence

`vectors/reference-nayuki.json` compares SpecQR's public generation API with the independently published `nayuki-qr-code-generator@1.8.0`. Every comparison generates both matrices at run time. Expected matrices are not generated by SpecQR, copied from its tests, or stored as snapshots that can be refreshed from SpecQR output.

## Oracle provenance

The [npm wrapper repository](https://github.com/maltsev/nayuki-QR-Code-generator) packages [Project Nayuki's QR Code generator](https://github.com/nayuki/QR-Code-generator). The installed source carries Project Nayuki's MIT copyright notice and points to the [upstream library description](https://www.nayuki.io/page/qr-code-generator-library). The wrapper is a third-party distribution; this Lab does not describe it as an official standards oracle or certification service.

## Committed scope

The 46 vectors retain the original numeric, alphanumeric, UTF-8 byte, mixed manual segment, ECI 26 and binary cases, then add:

- All 32 ECC/mask pairs (`L/M/Q/H` × masks `0..7`) using the same numeric payload at version 1.
- Mixed numeric/alphanumeric/byte segments at versions 6 and 7, straddling the start of version information, and versions 9/10 and 26/27, straddling character-count field widths. Byte counts change at 9/10 but remain 16 bits at 26/27; numeric and alphanumeric widths change at both boundaries.
- Exact single-byte-segment capacities at version 1-H (7 bytes), version 40-L (2,953 bytes), and version 40-H (1,273 bytes), with a deterministic binary pattern. Focused tests require both implementations to reject one more byte. These capacities are tested with no ECI header, explicit version/ECC/mask, and ECC boosting disabled.

`QrCode.encodeSegments` receives explicitly constructed numeric, alphanumeric or byte segments; version minimum and maximum are identical, mask is fixed, and ECC boosting is disabled. This removes optimizer and mask-selection differences from the comparison. Each positive result must pass `referenceMatrix.exact`, with the SpecQR and Nayuki matrix hashes both equal to a fresh independent oracle computation.

The focused test also changes one matrix module and changes one payload digit. Both negative controls must produce a matrix mismatch, and the single-module case must identify its exact coordinate. A temporary public-API wrapper corrupts a module from both `generate` and `generateSegments`; the real adapter must return `failed` for each selected target result, identifying that coordinate and different target/oracle hashes. This control detects accidental self-comparison or bypassing the selected target. The wrapper is deleted after the test and its results are never used as conformance evidence. Unsupported auto segmentation, Kanji, GS1/FNC1, ECI assignments other than the supported UTF-8 assignment, and Structured Append remain explicit skips in this reference lane.

## Reproduce

```sh
npm ci
node tools/test-reference-coverage.js
node tools/run-conformance.js --suite reference-nayuki --adapter nayuki --output reports/reference.local.json
```

The second command provides independent source provenance, coverage counts and negative-control evidence. The third produces per-vector live comparisons and hashes. Reports identify the installed SpecQR target separately; an RC target requires a fresh run and cannot inherit stable-target results.

This is bounded differential evidence for QR Code Model 2 generation. It does not claim exhaustive version/payload coverage, optimum segmentation, automatic mask quality, Kanji/GS1/Structured Append reference equivalence, scanning or renderer correctness, or official ISO/IEC certification. No text from a paywalled standard is included or treated as a directly verified source here.
